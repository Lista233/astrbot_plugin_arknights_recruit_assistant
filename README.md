# 明日方舟公招助手

明日方舟公开招募（公招）词条分析插件：发一张公招界面截图（或直接敲词条），
插件识别出 5 个词条后枚举 1~3 词条的**全部组合**，按星级收益排序给出推荐。

## 效果示例

![发送 /公开招募 + 两张截图，逐张识别后以合并转发返回](https://raw.githubusercontent.com/Lista233/astrbot_plugin_arknights_recruit_helper/main/pic/exp.jpg)

一条指令带多张公招截图 → 逐张识别词条 → 合并转发里每张截图各一条报告

## 功能

- **图片识别**：用多模态模型读图（当前对话模型、配置里指定的模型 ID，或另填一条独立的识图接口），不装任何额外依赖
- **多图批量**：一条消息发多张图、或分几条消息发图，每张各自识别；最多 3 张并发（5 张约 5s，串行约 11s）
- **合并转发**：识别结果默认以合并转发（聊天记录）发送，一张图一条记录，多张额外带总览，末尾固定附一条免责声明；只有 OneBot 系平台（NapCat / Lagrange 等）支持，QQ 官方机器人等平台自动改用普通文本
- **截图缓存**：先发截图、隔几条消息再发 `/公招` 也能识别（默认 3 分钟内有效）
- **等待补图**：反过来先发 `/公招` 再贴图也行（默认等 8 秒，收到新图再续 3 秒）
- **组合枚举**：5 个词条 → 最多 26 种组合，自动去重（候选池相同的组合只留最精确的那个）
- **优先级排序**：`必出6★` → `必出5★` → `保底4★+极小概率5★` → `保底4★` → `小概率5★` → `小概率4★`（仅 3★ 的档位不再展示）
- **高资优先抓取**：选了「高级资深干员」时，额外列出攻略推荐的「推荐优先抓取」干员名及其可用的词条组合（全部组合 + 出率，按出率排序）
- **桃金娘提示**：能凑出池子很小的桃金娘组合时单独提一句，其他 4★ / 5★ 不给具体干员推荐
- **资历池单独成条**：只勾中「高级资深干员」或「资深干员」时，报告只留结论，整池名单拆成单独一条消息（标题「高级资深干员池：」/「资深干员池：」）
- **按星级列全名单**：每个组合按 5★/4★/3★ 分组列出**全部**可能出现的干员
- **只留有价值的组合**：单词条只在带资历词条（高资/资深）或保底 4★ 以上时列出，如「快速复活」
- **单组名单**：`/公招干员 输出+生存` 查看某个组合的完整候选名单
- 纯离线数据：160 名公招干员由 Wiki 页面快照生成，运行时不联网

## 指令

| 指令 | 说明 |
| --- | --- |
| `/公开招募` | 三种顺序都行：图片带指令 / 先发 1~N 张截图再发 / 先发指令再贴图 |
| `/公开招募 输出 生存 近战位` | 直接输入词条，空格/逗号/顿号分隔均可 |
| `/公招干员 输出+生存` | 查看该词条组合的全部候选干员 |
| `/公招词条` | 列出全部公招词条（29 个） |
| `/公招帮助` | 指令说明 |

别名：`公招`、`公招分析`、`公招助手`、`明日方舟公招助手`、`公开招募小助手`（旧名保留）（其余指令同理带「公招」前缀）。

截图里的词条顺序、简称、错字都能容错，例如「高资」→ 高级资深干员、「术士」→ 术师、
「费用恢复」→ 费用回复；「近卫干员」这类带后缀的写法也能认，而界面上的
「职业需求」「点击刷新标签」不会被误判成词条。也可以直接把识别结果当文本粘进来。

## 判定规则

默认按 **9 小时**（`star_floor = 3`）计算：

1. 候选池 = 同时拥有全部所选词条的干员；池内最低星级即该组合的**保底星级**。
2. 6★ **必须**选中「高级资深干员」，否则永远不会出现 6★（数据上 6★ 干员只有带高资才进池）。
3. 5★ **必须**选中「资深干员」才标「必出 5★」；没有资深词条时，
   即使池内只剩 5★，也只标「小概率出 5★」。
4. 池内**没有 3★**（最低 4★）的组合 = **保底 4★**；其中池内还有 5★ 的单独列为
   「保底 4★+极小概率 5★」，排在纯「保底 4★」之前，同一候选池只出现一次。
5. 9 小时的星级下限是 3★，所以 1★ 小车（支援机械）、2★ 新手干员不会进池；
   想把 1★ 玩法算进来，把 `star_floor` 配成 1。
6. 没有一档保底 4★ 及以上时，报告只建议「不选词条」，不再罗列仅 3★ 的组合。
7. 只勾中一个资历词条时，报告只保留标题与结论，整池名单另发一条「高级资深干员池：」/
   「资深干员池：」，避免同一份名单在主报告里重复一次。
8. 星级概率（4★ / 5★ 的实际掉率）官方未公开，只有高资「优先抓取」段按池内人数
   给等概率出率（1/N，不考虑词条被划掉），其余只区分档位，不做伪概率估算。

## 高资优先抓取

词条里出现「高级资深干员」时，报告会在结论下多一段「推荐优先抓取」：
列出当前词条能凑出的、攻略《公开招募高级资深干员推荐 #11》（2026-08）
标为「优先抓取」的 6★。每名干员会列出**全部**可用组合及其出率
（池内人数等概率，不考虑词条被划掉），干员之间按出率从高到低排，
段尾附一行「（按概率排序，不考虑词条被划掉的情况）」。

结论行只给资历词条这一句（有高资就写「选择高级资深干员，拉满 9 小时必出 6★」，
只有资深就写「选择资深干员，拉满 9 小时必出 5★」），**不推荐具体组合**：
高资池里 6★ 很多，结论里点名容易被当成唯一答案。具体能点什么在下面的档位里。

- 前提是**推荐组合真的能点出来**：只有「高资 + 召唤」这类组合成立时才提示凯尔希，
  光靠「高资」35 人池去赌不算；组合里出现的词条也限定为本次识别到的词条，
  一条都凑不出来就整段不显示；
- 「推荐抓取」「随缘抓取」不做标记，4★ / 5★ 也不给具体干员推荐（桃金娘除外）；
- 名单在 `recruit_core.py` 的 `PRIORITY_SIX`，新干员进池后按同样格式补一行即可。

## 桃金娘提示

4★ 里唯一会点名的是桃金娘（产费核心）：某个组合池够小（≤ 2 人，出率 ≥ 50%）
且含桃金娘时，结论下多一行「选择「先锋+治疗」词条可获取桃金娘，建议优先抓取」。
池子大的组合不提示，避免把随缘写成推荐；阈值改 `recruit_core.py` 的
`TIP_FOUR_MIN_RATE`，换人改 `TIP_FOUR_OPERATOR`。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `recognize_mode` | `auto` | `auto` 用模型读图；`off` 关闭读图（只接受手动输入词条） |
| `provider_id` | 空 | 指定读图用的多模态模型 ID，留空用当前对话模型 |
| `custom_vision_enabled` | `false` | 开启自定义识图接口（不用 bot 里的模型） |
| `custom_vision_base_url` | 空 | 接口地址，如 `https://api.example.com/v1` |
| `custom_vision_model` | 空 | 模型名，如 `gpt-4o-mini`、`qwen-vl-max` |
| `custom_vision_api_key` | 空 | 接口秘钥（`Authorization: Bearer`） |
| `custom_vision_timeout` | `60` | 请求超时秒数 |
| `star_floor` | `3` | 时长对应的星级下限：9 小时 3、4 小时 2、1 小时 1 |
| `max_tags` | `3` | 每组组合最多几个词条（游戏上限 3） |
| `max_per_tier` | `6` | 每个优先级档位最多列几组 |
| `chunk_size` | `1200` | 单条消息最大字符数 |
| `image_cache_ttl` | `180` | 「先发截图、再发 `/公招`」的截图缓存秒数，填 `0` 关闭 |
| `image_wait` | `8` | 先发指令时等待截图的秒数，收到新图再续 3 秒；填 `0` 不等待 |
| `max_images` | `5` | 单次最多识别几张截图（上限 9） |
| `forward_result` | `true` | 识别结果用合并转发发送（仅 OneBot 系生效，其他平台自动发普通文本） |

### 读图识别

截图识别全走多模态模型，插件本身不需要额外依赖：默认用当前对话模型，也可以在
`provider_id` 里指定一个固定的视觉模型。

模型读不出来的常见原因：当前模型不支持图片、截图太糊、或者截图里没有「公开招募」
面板。这时直接输入词条即可，例如 `/公招 输出 生存 近战位`，结果与读图完全一致。

多张截图会并发识别（最多 3 张同时跑），单张失败只影响它自己；并发上限写在
`main.py` 的 `RECOGNIZE_CONCURRENCY`，碰到模型限流可以调到 1 变回串行。

### 自定义识图接口

不想用 bot 里配置的模型时，可以单独接一条 OpenAI 兼容的视觉接口：

1. `custom_vision_enabled` 打开；
2. `custom_vision_base_url` 填地址，如 `https://api.example.com/v1`
   （也接受 `https://api.example.com`、`https://ark.cn-beijing.volces.com/api/v3`、
   或完整的 `.../v1/chat/completions`，插件会自动补齐路径）；
3. `custom_vision_model`、`custom_vision_api_key` 填模型名与秘钥。

三项（地址 / 模型 / 秘钥）都填了才生效，此时 `provider_id` 与当前对话模型都不再参与；
关掉开关或缺任意一项就自动回到默认配置。图片以 `image_url` 方式发送
（链接图直接传 URL，本地图转成 base64 data URL），请求超时由 `custom_vision_timeout` 控制，
返回内容解析不到词条时按识别失败处理，不会静默回退。

## 平台兼容

| 平台 | 文字分析 | 图片识别 | 合并转发 |
| --- | --- | --- | --- |
| `aiocqhttp`（NapCat / Lagrange 等） | 支持 | 支持 | 支持 |
| QQ 官方机器人（`qq_official` / `qq_official_webhook`） | 支持 | 支持（附件 URL 需能被模型服务访问） | 不支持，自动改普通文本 |
| 其他适配器 | 支持 | 支持 | 自动改普通文本 |

QQ 官方机器人的几个注意点：

1. **合并转发不支持**：AstrBot 的 QQ 官方适配器会静默丢掉 `Nodes` 组件（只打一条 debug 日志），
   所以插件会先判断平台，非 OneBot 系直接用普通文本发送，否则用户会什么都收不到。
2. **只能收到 @ 机器人的消息**：公域机器人拿不到没 @ 它的群消息，所以
   「先发截图、再发 /公招」的截图缓存基本用不上；直接在 @ 机器人时把图和指令一起发，
   或者在私聊里用。
3. **被动回复次数有限**：同一条消息的被动回复有次数上限（约 5 条/5 分钟），
   多图批量识别容易超限，建议单次 1~2 张，必要时把 `max_images` 调小。
4. **图片走附件 URL**：收到的图片组件是 `image_url` 形式的临时链接，模型侧要能直接拉到；
   拉不到时插件会先下载到本地再转 base64（自定义识图接口），仍失败就改用文字输入。

## 数据更新

干员数据在 `data/recruit_data.json`，由 Wiki 公招页面的 HTML 快照解析生成：

```bash
python tools/build_recruit_data.py [template-html.html 路径]
```

脚本读取每个干员卡片的 `data-param1`（职业/星级）与 `class="tagText"` 词条，
合并成「职业 + 部署位置 + 特性词条」，按星级排序后写入 JSON 并打印星级分布，
方便核对新池子是否解析正确。

## 目录结构

```
astrbot_plugin_arknights_recruit/
├── main.py                  # 插件入口：指令注册、图片获取、模型读图
├── recruit_core.py          # 词条归一化、组合枚举与排序、文本排版（与 AstrBot 解耦）
├── data/recruit_data.json   # 干员数据（160 人）
├── pic/exp.jpg              # README 效果示例图
├── tools/build_recruit_data.py  # 由 Wiki 快照生成数据
├── requirements.txt         # 无额外依赖（保留占位）
├── _conf_schema.json
└── metadata.yaml
```

`recruit_core.py` 不依赖 AstrBot，可以单独跑：

```bash
python -c "import recruit_core as rc; db=rc.load_database(); print(rc.render_report(db, ['输出','生存','近战位']))"
```
